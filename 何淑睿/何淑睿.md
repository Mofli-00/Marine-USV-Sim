## 5月7日

### 渲染效果异常排查：团结引擎画面过白问题

本周天气系统脚本逻辑已基本搭建完成，但在团结引擎中实际测试雨天、雾天效果时，发现一个核心问题：**无论如何调整代码中的曝光、色调、雾浓度等参数，画面始终呈现过曝发白的状态，天气切换的视觉效果完全无法正常显示**。

- 排查过程中尝试了多种思路：通过脚本直接修改 `RenderSettings`（雾效、环境光）、调整 `Directional Light` 的强度与颜色、创建 URP `Volume` 并配置 `Color Adjustments`（曝光、饱和度、对比度）与 `Vignette`（暗角）等后处理参数。即便在运行时手动将 Volume 的 Weight 拖到最大、Post Exposure 大幅调低，画面依旧没有明显变化，问题没有得到解决。

### 原因排查与分析

回溯项目获取方式后，进一步排查出两个可能导致该问题的原因：

- **项目下载方式不完整**：自己最初是通过 GitHub 页面直接下载 ZIP 压缩包的方式获取 Boat Attack 项目源码，而队友提醒应使用 `git clone`（配合 Git LFS）的方式下载。查阅资料确认，GitHub 在生成 ZIP 源码包时，仓库中由 **Git LFS** 管理的大文件（如贴图、Lightmap 烘焙数据、HDR 天空盒、Cubemap 等）默认可能不会被完整打包进 ZIP，而是替换为指针文本文件。若项目中的光照贴图、天空盒等关键渲染资源因此缺失或损坏，会直接导致 Volume 后处理（曝光、色调映射等）失去其依赖的基础数据，从而出现画面整体过曝发白、参数调整无明显效果的现象，这与本周遇到的问题表现高度吻合。
- **引擎渲染管线差异**：团结引擎作为 Unity 的本地化定制版本，在色彩空间处理、Tonemapping（色调映射）算法实现、Volume Profile 默认生效逻辑等方面，可能与原版 Unity 的 URP 存在细微差异。
### 解决方式

- 与队友沟通确认后，决定暂时搁置在团结引擎中继续排查渲染层面的差异，改为**在 Unity 中重新尝试天气系统的视觉效果实现**，以验证是否为资源缺失或引擎差异导致的问题。
- 后续如有条件，计划改用 `git clone` 配合 Git LFS 的方式重新获取一份完整项目源码，对比验证光照贴图、天空盒等资源是否完整，以进一步确认根本原因。



# 4月30日

### 1. 天气控制脚本编写

在插件导入成功的基础上，开始编写适配 Boat Attack 项目的天气控制脚本。

- 原版 `WeatherControl` 脚本设计为挂载在 Camera 上运行，但 Boat Attack 使用 Cinemachine 虚拟相机系统，直接挂载会导致引用获取错误。改写为独立脚本 `WeatherControl_BoatAttack.cs`，挂载在场景中一个空 GameObject 上，通过 `LateUpdate` 让雨雪粒子的位置跟随主相机（`Camera.main`），从而绕开 Cinemachine 带来的兼容性问题。
- 新增晴天、雨天、雾天、雪天四种天气的渐变切换逻辑，使用协程（Coroutine）实现天气间的平滑过渡，过渡时间可在 Inspector 中调整。
- 同步编写 `WeatherUI.cs`，使用 Unity 内置 OnGUI 实现一个可呼出的天气选择面板（按 Tab 键切换显示），包含四个天气按钮，并在屏幕角落实时显示当前天气状态，便于调试和演示。

### 2. 场景配置与首次联调

- 在 `demo_island` 场景中创建 `WeatherSystem` 空对象并挂载上述两个脚本，配置雨/雪预制体、音效等引用。
- 运行测试中发现 Tab 键完全无响应，排查后定位为 Boat Attack 项目已启用新版 Input System，而脚本中使用的 `Input.GetKeyDown` 属于旧版输入接口，触发 `InvalidOperationException`。
  - **解决方式**：在 `Project Settings → Player → Active Input Handling` 中将设置改为 `Both`，使新旧两套输入系统可以同时工作，问题解决。

### 3. 背景音乐联动调试

- 初版效果中，天气切换时背景音乐完全盖过了雨声，且画面明暗变化不明显。
- 在脚本中新增背景音乐音量自动控制逻辑：切换到雨天/雾天时，自动将场景内其余 AudioSource 音量降至原来的 15%-40%，雨声/雷声音量同步提升，切回晴天后自动恢复原音量。

# 4月16日

### 1. 天气系统方案调研

本周开始着手为 `Boat Attack` 项目设计并实现天气系统，作为对原项目的改进点之一。

- **方案对比**：组内讨论了两种实现思路，分别是付Unity/团结引擎内置功能手动搭建和免费开源插件 + 自写控制脚本。本人着手尝试导入免费开源插件+自写控制脚本。

### 2. 插件导入尝试

- **第一次尝试（失败）**：在 GitHub 上找到开源项目 `aspect-ux/WeatherSystem`，导入后出现 `AtmosphereSettings` 类型缺失的编译错误。排查后发现该插件依赖外部库 `sinnwrig/URP-Atmosphere`，补充导入依赖后又引发 URP Settings 与项目原有 ProjectSettings 配置文件冲突，报错数量不降反增（Renderer 资源解析失败、RendererFeatures 缺失等）。判断该插件与当前渲染管线兼容性过低，最终放弃此方案。
  - 直接复制插件文件夹导致 ProjectSettings、Renderer 等全局配置被意外覆盖。

- **第二次尝试（成功）**：改为尝试 `MarcusXie3D/MobileWeatherSystem`（GitHub 开源项目）。吸取第一次失败的教训，未直接拷贝 Assets 文件夹，而是使用该项目提供的 `.unitypackage` 打包文件，通过 `Assets → Import Package → Custom Package` 方式导入，避免了配置文件被覆盖的问题。导入后 Console 仅有黄色警告，无红色编译错误。

### 3. 插件内容确认

通过 Project 面板搜索确认插件提供的核心组件：

- 雨效：`rainManager`、`RainBox`、`RainManager` 脚本，以及 `RainStreak`、`RainDrops` 贴图资源
- 雪效：`snowParticles`、`SnowParticle` 脚本与材质
- 总控制脚本：`WeatherControl`
- 音效：`rain_only`（雨声）、`thunder_rain`（雷声）

### 遇到的问题

- 第一个候选插件依赖链复杂，且与项目原有 URP 配置直接冲突，修复一处报错常引出新报错，排查成本高。
- 最初以直接复制文件夹方式导入插件资源，导致项目全局配置被覆盖。

### 解决方式

- 放弃依赖链复杂、兼容性差的插件，改用结构独立、提供标准 `.unitypackage` 导入方式的开源插件。
- 明确后续导入第三方资源统一使用 `.unitypackage` 方式，降低与项目配置冲突的风险。
